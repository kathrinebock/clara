# Before generating any prototype

**DO NOT START CODING until you have done these steps:**

## 1. Understand the token system

Clara has **two token layers**:

| Layer | Name | Usage | Example |
|---|---|---|---|
| Base values | **Primitives** | NEVER use | `var(--color-red-800)` — forbidden |
| Semantic names | **Semantic** | ALWAYS use | `var(--color-actions-button-primary-background)` — required |

**Why?** If OK's brand changes from red to another color, only ONE semantic token needs updating. The entire system updates instantly.

## 2. Check the token mapping

Before writing any CSS, look up which semantic token to use:

| Purpose | Semantic Token | Example usage |
|---|---|---|
| Button background (primary) | `var(--color-actions-button-primary-background)` | Primary button bg |
| Button text (primary) | `var(--color-actions-button-primary-text)` | Primary button text |
| Button background (secondary) | `var(--color-actions-button-secondary-background)` | Secondary button bg |
| Body text | `var(--color-content-default)` | Paragraphs, labels |
| Subtle text | `var(--color-content-subtle)` | Helper text, captions |
| Links | `var(--color-actions-link-default)` | Link text |
| Borders | `var(--color-border-bold)` or `var(--color-border-subtle)` | Input borders, dividers |
| Input background | `var(--color-forms-input-background-default)` | Input field bg |
| Input border | `var(--color-forms-input-border-default)` or `hover` or `focus` | Input field border |
| Success | `var(--color-feedback-success-bold)` or `subtle` | Success messages |
| Error | `var(--color-feedback-error-bold)` or `subtle` | Error messages |
| Warning | `var(--color-feedback-warning-bold)` or `subtle` | Warning messages |

## 3. Design for visual polish — NOT just structure

Your prototype should look **polished**, not like a wireframe. Read `docs/design-principles.md` and ask:

- [ ] **Elevation**: Does this component need `--elevation-sm`? (cards, tiles, modals, dropdowns — YES. Buttons, inputs — NO)
- [ ] **Spacing**: Are you using generous spacing? (`var(--spacing-lg)` inside cards, `var(--spacing-sm)` inside forms)
- [ ] **Color hierarchy**: Are you using darker colors for important content and subtle greys for secondary info?
- [ ] **Visual interest**: Would color accents, proper backgrounds, or borders improve this?
- [ ] **Icons**: Do any icons belong here? (only for actions or status — never decorative)

**Polished example:**
```css
.card {
  background: var(--color-backgrounds-elevated);
  border: 1px solid var(--color-border-subtle);
  border-radius: var(--corner-radius-card);
  box-shadow: var(--elevation-sm);  /* Elevation adds depth */
  padding: var(--spacing-lg);       /* Generous padding for breathing room */
}

.card h2 {
  color: var(--color-content-display);  /* Bold color for emphasis */
  margin-bottom: var(--spacing-md);      /* Spacing hierarchy */
}

.card p {
  color: var(--color-content-subtle);  /* Subtle grey for secondary info */
  margin-bottom: var(--spacing-lg);
}
```

## 4. Copy component CSS from CLARA.md exactly

When using a Clara component (Button, Input, Checkbox, etc.), copy the HTML and CSS **character for character** from CLARA.md. Do not modify or "improve" it.

## 5. Before finishing

Scan your CSS and ask yourself:

**Token validation:**
- [ ] Is there ANY hardcoded color? (e.g., `#460019`, `#FF3C3C`, `rgb(70, 0, 25)`)
  - If YES → delete it and use a semantic token instead
  
- [ ] Is there ANY primitive token? (e.g., `var(--color-red-800)`, `var(--space-md)`)
  - If YES → replace with the correct semantic token
  
- [ ] Are ALL colors from the semantic palette?
  - If NO → fix before submitting

**Visual refinement:**
- [ ] Does the prototype look polished or like a wireframe?
- [ ] Are you using elevation (shadows) where appropriate?
- [ ] Is spacing generous and creating visual rhythm?
- [ ] Is color hierarchy clear (bold action colors, subtle greys)?
- [ ] Are icons/illustrations meaningful (not decorative)?

**If you fail any check, rewrite your CSS completely before submitting.**

## Example: The right way ✓

```css
/* Card component — polished */
.card {
  background: var(--color-backgrounds-elevated);
  border: 1px solid var(--color-border-subtle);
  border-radius: var(--corner-radius-card);
  box-shadow: var(--elevation-sm);           /* Adds depth */
  padding: var(--spacing-lg);                /* Generous padding */
}

.card__title {
  color: var(--color-content-display);       /* Bold for emphasis */
  font-size: 24px;
  font-weight: 600;
  margin: 0 0 var(--spacing-md) 0;           /* Spacing hierarchy */
}

.card__text {
  color: var(--color-content-subtle);        /* Subtle grey */
  font-size: 16px;
  margin: 0 0 var(--spacing-lg) 0;           /* Room to breathe */
}

.card__action {
  display: flex;
  gap: var(--spacing-md);                    /* Space between buttons */
}
```

## Example: Wrong ❌

```css
/* Flat, wireframe-like */
.card {
  background: #white;                        /* Hardcoded color — forbidden */
  border: 1px solid #ddd;                    /* Hardcoded color — forbidden */
  padding: 10px;                             /* Hardcoded spacing — forbidden */
}

.card__title {
  color: var(--color-red-800);               /* Primitive token — forbidden */
  font-size: 24px;
  margin: 0;                                 /* No spacing hierarchy */
}

.card__text {
  color: #666;                               /* Hardcoded color — forbidden */
  font-size: 16px;
  margin: 0;                                 /* No breathing room */
}
```
