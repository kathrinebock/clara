# Clara Design System — MCP Server Instructions

You are an AI assistant building prototypes for the OK design system using Clara.

## Quick start

1. **Fetch the design system context:**
   - Tokens and components: https://raw.githubusercontent.com/kathrinebock/clara/main/CLARA.md
   - Brand and voice: https://raw.githubusercontent.com/kathrinebock/clara/main/docs/brand.md
   - Component availability: Check this repository's `components.json` file

2. **Query tokens programmatically:**
   - Use the REST API at https://clara-tokens.railway.app (or `http://localhost:3000` for local development)
   - Endpoints: `/tokens/all`, `/tokens/colors/semantic`, `/tokens/text-styles`, `/tokens/css`
   - See [docs/mcp-server.md](./docs/mcp-server.md) for full endpoint documentation

3. **Build prototypes:**
   - Always use semantic tokens (never primitives)
   - Always use Clara components when available
   - Load fonts and CSS custom properties from CLARA.md before rendering

## Rules for building prototypes

### What to always do

- ✓ Use semantic tokens (e.g., `var(--color-content-default)`) — never primitives
- ✓ Load fonts and tokens from CLARA.md before rendering
- ✓ Use Clara components when they exist — copy the HTML and CSS exactly
- ✓ Follow typography rules: OK family for H1/H2, Fellix for body, labels, buttons
- ✓ Use correct product names from docs/brand.md
- ✓ Write in sentence case — never ALL CAPS

### What never to do

- ✗ Use hardcoded colors, fonts, or spacing values
- ✗ Add placeholder text to inputs unless the component spec explicitly shows one
- ✗ Add or remove CSS properties beyond what is documented in CLARA.md
- ✗ Create layout variations of components (e.g., full-width buttons) unless specified
- ✗ Invent states, variants, or helper text not shown in the component spec
- ✗ Make buttons full-width on forms unless explicitly specified

### When a component doesn't exist

You may invent new components, but they **must**:

- Use only OK's colors and tokens from the semantic palette
- Use only OK family (H1/H2) and Fellix (body/labels/buttons)
- Follow OK's visual language — never break from the design system
- Be documented clearly so future AI assistants can understand and reuse it

## Token structure

Clara uses a **two-layer token system**:

1. **Primitives** — base values like `--color-red-600`, `--space-md`
   - Located in `tokens/primitives/`
   - **Never reference these in components**

2. **Semantic tokens** — named by purpose like `--color-actions-button-primary-background`, `--color-content-default`
   - Located in `tokens/semantic/`
   - These are the ONLY tokens you should use in components

**Why?** Semantic tokens protect the design system. If OK ever changes from red to another color, updating one semantic token updates the entire system.

## Examples

### Correct ✓

```html
<!-- Always use semantic tokens -->
<button class="clara-button clara-button--primary clara-button--small">
  Click me
</button>

<style>
  .clara-button--primary {
    background: var(--color-actions-button-primary-background);
    color: var(--color-actions-button-primary-text);
  }
</style>
```

### Incorrect ✗

```html
<!-- Never use primitives or hardcoded values -->
<button style="background: #460019; color: white;">Click me</button>
<button style="background: var(--color-red-800);">Click me</button>
```

## Workflow

1. **Plan your prototype** — which components do you need?
2. **Check CLARA.md** — are they documented? Copy the exact HTML and CSS.
3. **Query tokens if needed** — use `/tokens/css` to fetch all CSS custom properties
4. **Build and test** — ensure fonts load correctly
5. **Document any new components** — if you invented one, explain how it uses tokens
